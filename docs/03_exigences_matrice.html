Étape 3 : Exigences & Matrice de Traçabilité

Atelier Test et Validation des Logiciels • Licence 3 Technologies de l'Information

Cadrage Méthodologique & Objectifs du Livrable
Formalisation des exigences fonctionnelles et sécuritaires sous forme de critères d'acceptation Given-When-Then (Gherkin). Établissement de la matrice de traçabilité garantissant une couverture intégrale des risques identifiés à l'étape 1.

1. Analyse de Testabilité et Ambiguïtés Levées

Peut-on mettre une note de 3.5 ?

NON. Seuls les entiers stricts (1, 2, 3, 4, 5) sont acceptés.

Un produit peut-il coûter 0€ ?

OUI. Le prix doit être ≥ 0 (un cadeau ou échantillon est possible, mais pas -10€).

Peut-on modifier l'avis d'un autre client ?

NON. Seul l'auteur de l'avis ou l'admin a ce droit (sécurité RBAC).

Combien de caractères pour le mot de passe ?

Entre 6 et 50 caractères. En dessous de 6, le compte est refusé.

2. Critères d'Acceptation Formels (Given – When – Then)

Chaque fonctionnalité est testée avec une formule universelle : Étant donné (Given) → Quand (When) → Alors (Then).

EX-01 : Inscription d'un Utilisateur Test Positif

GIVEN Un visiteur fournit un email non utilisé et un mot de passe de 8 caractères.
WHEN Il clique sur le bouton "Créer mon compte".
THEN Le compte est créé avec succès (HTTP 201) et le mot de passe est crypté en base.

EX-02 : Sécurité des Droits (RBAC) Test Négatif

GIVEN Un utilisateur ordinaire connecté avec le rôle user.
WHEN Il tente d'appeler l'API de création d'un produit (réservée à l'admin).
THEN Le serveur refuse immédiatement avec une erreur HTTP 403 Forbidden.

EX-03 : Validation du Prix Valeur Limite

GIVEN Un administrateur qui essaie d'ajouter un produit avec un prix négatif de -15€.
WHEN Il valide le formulaire.
THEN Le backend bloque la requête avec une erreur HTTP 400 Bad Request.

EX-04 : Note d'Avis Produit Règle Métier

GIVEN Un client connecté sur la page d'un produit acheté.
WHEN Il sélectionne 5 étoiles et écrit "Très satisfait".
THEN L'avis est enregistré et la note moyenne du produit est recalculée.

3. Matrice de Traçabilité (Exigences ↔ Risques ↔ Tests)

Cette matrice prouve qu'aucune exigence n'est oubliée et que chaque test correspond à un vrai besoin :

Exigence Règle / Fonction Risque Couvert Niveau de Test Outil Utilisé
EX-01 Inscription & Login JWT Token invalide ou usurpation API REST + Unitaire Postman / Jest
EX-02 Contrôle RBAC (User vs Admin) Élévation de privilèges Intégration + API Supertest / Postman
EX-03 Produit : Prix positif (≥ 0) Prix négatif / fraude Unitaire (DTO) Jest
EX-04 Avis : Note entre 1 et 5 Fausse note ou crash calcul Unitaire + BDD Jest + PostgreSQL
EX-05 Liaison Produit ↔ Avis Données orphelines (Crash 500) Intégration BDD TypeORM / Jest
EX-06 Parcours d'achat complet Écran blanc / 404 Nginx Interface (E2E) Playwright
