Étape 8 : Tests de l'API REST (Postman / Supertest)

Atelier Test et Validation des Logiciels • Licence 3 Technologies de l'Information

Cadrage Méthodologique & Objectifs du Livrable
Campagne de tests d'API REST via Postman et Supertest. Validation des statuts HTTP (200, 201, 400, 401, 403, 404), de la conformité des payloads JSON et de l'étanchéité des contrôles d'accès basés sur les rôles (RBAC).

1. Protocole de Validation de l'API REST

1. Codes de Statut HTTP

200 (OK), 201 (Créé), 400 (Mauvaise requête), 401 (Non connecté), 403 (Accès interdit), 404 (Introuvable).

2. En-têtes (Headers)

Présence de Content-Type: application/json et gestion du header Authorization: Bearer <token>.

3. Structure du JSON (Schéma)

Le corps de la réponse contient bien les clés attendues (id, email, price) sans données secrètes (ex: mot de passe jamais renvoyé !).

4. Gestion Propre des Erreurs

En cas d'erreur de saisie, renvoyer un message d'erreur clair et lisible plutôt qu'un crash serveur 500.

2. Synthèse d'Exécution de la Suite API

Méthode & Endpoint Description & En-têtes Payload Envoyé Statut HTTP Attendu Résultat
POST /auth/login Connexion réussie { "email": "admin@nestlearn.com", "password": "..." } 200 OK (avec access_token) PASS
POST /auth/login Échec mot de passe erroné { "email": "admin@nestlearn.com", "password": "faux" } 401 Unauthorized PASS
POST /products Création avec compte admin Bearer Token (Admin) + { "name": "Clavier", "price": 40 } 201 Created PASS
POST /products Tentative création sans token Aucun header Authorization 401 Unauthorized PASS
POST /products Tentative création avec compte simple client Bearer Token (User) 403 Forbidden PASS
GET /products Consultation publique du catalogue Public (aucun token nécessaire) 200 OK (Tableau JSON) PASS
DELETE /reviews/9999 Suppression d'un avis inexistant Bearer Token 404 Not Found PASS
