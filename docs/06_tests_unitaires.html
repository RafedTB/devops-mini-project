Étape 6 : Tests Unitaires Automatisés (Jest)

Atelier Test et Validation des Logiciels • Licence 3 Technologies de l'Information

Cadrage Méthodologique & Objectifs du Livrable
Automatisation des tests unitaires isolés avec Jest et TypeORM repository mocks. Application systématique du pattern Arrange-Act-Assert (AAA) et mesure de couverture de code (83.8% de couverture de code, dépassant le seuil exigé de 75%).

1. Méthodologie et Structure Arrange – Act – Assert (AAA)

1. ARRANGE (Préparer)

On initialise les fausses données et les mocks de la base de données.

2. ACT (Agir)

On appelle la méthode du service qu'on veut tester (ex: createProduct()).

3. ASSERT (Vérifier)

On vérifie avec expect(...) que le résultat est conforme à l'attendu.

// Exemple réel de test unitaire Jest dans src/reviews/reviews.service.spec.ts it('devrait créer un avis avec succès si la note est entre 1 et 5', async () => { // 1. ARRANGE const dto = { rating: 5, comment: 'Excellent produit !' }; mockReviewRepo.save.mockResolvedValue({ id: 1, ...dto }); // 2. ACT const result = await reviewsService.createReview(1, dto, { id: 10 }); // 3. ASSERT expect(result).toBeDefined(); expect(result.rating).toBe(5); expect(mockReviewRepo.save).toHaveBeenCalled(); });

2. Isolation des Dépendances (Test Doubles & Mocks)

Un test unitaire doit tester uniquement la logique du service, sans dépendre de la vraie base de données.

  • Vitesse : Les tests s'exécutent en quelques millisecondes dans la RAM.
  • Indépendance : Pas besoin d'allumer PostgreSQL pour faire tourner les tests unitaires.
  • Contrôle total : On peut simuler facilement un plantage (ex: simuler que la BDD renvoie une erreur).
