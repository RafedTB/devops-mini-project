Étape 7 : Tests d'Intégration & Base de Données (PostgreSQL)

Atelier Test et Validation des Logiciels • Licence 3 Technologies de l'Information

Cadrage Méthodologique & Objectifs du Livrable
Validation de la persistance réelle et de l'intégrité relationnelle sous PostgreSQL. Vérification des contraintes d'unicité, des suppressions en cascade (ON DELETE CASCADE) et mise en place de transactions isolées avec nettoyage automatisé.

1. Objectifs des Tests d'Intégration et Persistance

Test Unitaire (Étape 6)

Utilise de faux objets (mocks). Il teste si le code TypeScript réfléchit bien, sans toucher au disque dur ni au réseau.

Test d'Intégration (Étape 7)

Envoie de vraies requêtes SQL INSERT, SELECT, DELETE dans PostgreSQL pour vérifier la persistance réelle.

2. Validation de l'Intégrité Relationnelle (PostgreSQL)

ID Test Cible & Opération Scénario Exécuté Vérification SQL / ORM Résultat
INT-01 CRUD Produit persistant Créer un produit → Relire par son ID → Modifier son prix → Supprimer. La ligne existe bien dans la table products et disparaît après DELETE. PASS
INT-02 Contrainte d'unicité Email Tenter d'insérer 2 utilisateurs avec le même email duplicate@test.com. PostgreSQL déclenche une erreur d'intégrité unique_violation interceptée. PASS
INT-03 Intégrité relationnelle (FK) Lier un avis à un produit existant (ID: 1) puis tenter de lier à un produit inexistant (ID: 9999). L'avis valide est persisté ; l'avis avec fausse clé étrangère est rejeté par la BDD. PASS

3. Gestion de l'Isolement et Nettoyage des Données

  • Base isolée : Les tests tournent sur devops_test pour ne pas effacer les comptes de dev.
  • Nettoyage automatique (Hooks) :
    • beforeAll() : Initialise la connexion TypeORM et lance les migrations.
    • afterEach() : Nettoie les tables de test pour que le test suivant reparte de zéro.
    • afterAll() : Ferme proprement la connexion à la base.
