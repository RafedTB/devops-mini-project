Étape 2 : Plan de Test & Stratégie Globale

Atelier Test et Validation des Logiciels • Licence 3 Technologies de l'Information

Cadrage Méthodologique & Objectifs du Livrable
Cette étape formalise la stratégie globale de test en s'appuyant sur la pyramide des tests, l'isolation rigoureuse des environnements (développement, test, production via Docker) et la définition explicite des critères d'entrée et de sortie de campagne.

1. Stratégie Multi-Niveaux (Pyramide des Tests)

On commence par tester les briques de base (rapides), puis on monte jusqu'au vrai utilisateur :

5. Performance Outil : k6
4. Interface (E2E) Outil : Playwright
3. API REST Outil : Postman
2. Intégration & BDD Outil : Jest + PostgreSQL
1. Tests Unitaires Outil : Jest
1. Tests Unitaires

On teste une seule fonction isolée dans le code. Exemple : est-ce que la note refuse 0 et 6 ?

2. Tests d'Intégration

On teste si le serveur arrive à enregistrer et lire correctement dans la base de données PostgreSQL.

3. Tests API REST

On envoie des requêtes HTTP (POST, GET) et on vérifie qu'on reçoit le bon code (200 OK, 401 Non autorisé).

4. Test E2E Interface

Un robot ouvre le navigateur Chromium, remplit le formulaire de login et clique sur les boutons comme un humain.

5. Test de Performance

On simule 20 personnes connectées en même temps pour vérifier que le site répond en moins de 0.5 seconde.

2. Environnements de Test et Déploiement

ENV 1 : Dev Local

Pour écrire le code et tester vite sur son PC en direct.

ENV 2 : Test Automatique

Utilise une base de données séparée (devops_test) pour ne pas polluer les vraies données.

ENV 3 : Docker Staging

L'application complète tourne dans des conteneurs Docker (exactement comme en vrai).

3. Critères d'Entrée et Critères de Sortie

Critères d'Entrée (Entry Criteria)

  • Le projet compile sans aucune erreur (npm run build).
  • La base de données est accessible.
  • On a préparé des fausses données de test (seeders).

Critères de Sortie (Exit Criteria)

  • Couverture de code : au moins 75% du backend testé.
  • Zéro bug bloquant : aucun crash du serveur ou trou de sécurité.
  • Succès des tests : au moins 95% des tests passent au vert.
  • Vitesse : le site répond en moins de 0.5 seconde.

4. Procédure de Suspension et Reprise des Tests

  • Suspension (On fait pause) : Si le système de connexion plante totalement ou si la base de données ne répond plus, on arrête les tests immédiatement et on signale le problème.
  • Reprise : Une fois le bug corrigé par un correctif, on rejoue d'abord le test du bug, puis on relance tous les tests pour vérifier qu'on n'a rien cassé d'autre.
